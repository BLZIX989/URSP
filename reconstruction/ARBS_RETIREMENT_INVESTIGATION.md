# Investigation: why does the NCG workbook call ARBS "retired"?

**Question:** does `AUD-010` ("ARBS — legacy only — RETIRED / PRESERVED — not canonical foundation")
reflect a specific finding that actually supersedes the graph/seed work from runs 1–16, or is it a
separate research thread that never engaged with it?

## Finding: separate thread, no technical engagement, no specific refutation

Four independent pieces of evidence, all pointing the same direction:

1. **Zero mentions of any specific graph-theoretic object this project built.** Searched every one
   of the workbook's 156 sheets for `tilde G_k`, `K_{2^k,2^k}`, `Gamma_infty`, `R*`, `bipartite`,
   `shell`, `Rosetta` — **zero hits, all seven terms.** A document that had actually tested and
   rejected the specific `tilde_G_k`/`Γ_∞`/`R*` construction would show some trace of engaging with
   it. There is none, anywhere in 156 sheets.

2. **Zero mentions of the specific gauge-route documents this project already found and rejected.**
   `SEF` (the `SEF SIT Specification v2.docx` that contains the graph-automorphism route,
   found and rejected in `KIJ-THETA-IMAGE-RECOVERY-001`): zero hits. `graph automorphism`: zero hits.
   This workbook's own NCG derivation route is entirely independent of, and doesn't reference, the
   *other* rejected gauge-derivation attempt already documented in this project's source corpus —
   evidence these are two separately-developed threads, not one continuous investigation.

3. **The DTC grammar itself barely appears.** `DTC`, `Delta` (as the Distinction primitive),
   `Psi_{t+1}` (the recursion), `organizational grammar`: zero hits. `Constraint`/`Transformation`
   appear only as generic English words in unrelated contexts (8 and 10 hits respectively, none in
   the D/T/C formalism sense). A document that had actually worked through and refuted this project's
   specific primitive grammar would show some engagement with its notation. There is none.

4. **The retirement itself carries no citation.** Every other status claim in this same workbook
   cites a specific `V2-CALC-NNN` calculation ID as evidence (e.g. `AUD-007`: "A_F uniqueness —
   partial within ansatz — PRESERVED — global theorem open", tied to `OPEN-001`/`V2-CALC-016/017`).
   `AUD-010`'s ARBS row cites **no calculation ID, no test, no falsification event** — it reads as a
   **scope-setting governance line** ("this document's approach is NCG-first; ARBS is not what we're
   building on here"), not a technical verdict reached by testing and refuting ARBS's own claims.

**Timing corroborates this.** Every `V2-CALC` entry in the execution history is dated `2026-08-17` —
the day before this session's 16 runs, whose own headers all read `2026-08-18`. The most parsimonious
explanation is that this NCG workbook was produced by a separate conversation or session, run in
parallel with (or just before) this session's ARBS/graph-seed sequence, pursuing its own research
program with its own internal governance choice to center on NCG — without ever being reconciled
with, or technically engaging, the graph-theoretic thread this session has been building.

## Conclusion

**`AUD-010` is a scoping decision by a parallel, non-engaging research thread, not a technical
refutation of this session's graph/seed work.** It does not constitute evidence that `tilde_G_k`,
`TH-ARBS-001A/B`, `Γ_∞`, or the `F_N^derived` seed family are wrong, inadequate, or superseded — no
test was ever run against them by this document. It *does* mean the project's source corpus now
contains two independently-developed, non-merged architectural proposals for the same overall goal:
this session's graph/ARBS-based compiler kernel, and this newly-found workbook's NCG-based physical
foundation. Reconciling them — building the "semantic functor" both documents separately flag as
`OPEN` (`OPEN-024` here; nothing analogous ever attempted in the graph-seed runs) — remains a real,
unresolved task, not something either thread has actually closed for the other.

## What this does not resolve

This investigation deliberately does not recommend switching architecture, retiring ARBS, or merging
the two threads — that was explicitly out of scope for this run's question. It only establishes
*why* the retirement label exists, so that decision (if and when made) rests on accurate grounds
rather than on `AUD-010`'s bare assertion.
